#### 生命周期 API

| API | 文件:行 | 说明 |
|-----|--------|------|
| `void app_cfg_init(void)` | [app_cfg.c](../main/config/app_cfg.c) | 创建 mutex + nvs_flash_init + nvs_open("cfg") + 读 NVS + 校验 + 迁移（迁移后无条件落盘） |
| `void app_cfg_load(void)` | 同上 | 别名，直接调用 `app_cfg_init()` |
| `void app_cfg_save(void)` | 同上 | **延迟落盘**（C1 去抖）：仅标记脏，由 1s esp_timer 统一写 NVS，防高频 setter 磨损 Flash |
| `void app_cfg_flush(void)` | 同上 | **立即同步落盘**（关机/配网/手动保存场景） |
| `size_t app_cfg_get_last_ssid(char *buf, size_t buf_len)` | 同上 | 线程安全读取 last_ssid |

#### Getter API（节选）

`app_cfg_get_lang` / `_brightness` / `_dim_s` / `_off_s` / `_clock_x` / `_clock_y` / `_clock_size` / `_clock_rgba` / `_show_ms` / `_show_seconds` / `_show_clock` / `_clock_text`（返回内部指针，**非线程安全**）/ `_bg_mode` / `_bg_refresh_s` / `_bg_url`（内部指针）/ `_bg_color` / `_quotes_sym_l` / `_quotes_sym_r` / `_quotes_refresh_s` / `_quotes_up_rgba` / `_quotes_down_rgba`。

> **2026-08 更新**：`app_cfg_get_canvas_w/h` 已删除（画布尺寸是硬件信息，改用 `disp_driver_get_canvas_w/h`）。

#### Setter API（每个内置 publish + 延迟 save）

每个 setter 流程：**值裁剪 → 写 g_cfg → `cfg_publish(CFG_FIELD_*)` → 必要时发衍生事件 → 标记脏（延迟落盘）**。事件实时通知订阅者，磁盘写入延迟合并。

| 分类 | Setter | 衍生事件 |
|------|--------|---------|
| 时钟 | `set_show_seconds` / `set_show_clock` / `set_clock_text` / `set_clock_pos` / `set_clock_size` / `set_clock_rgba` / `set_show_ms` | `EVENT_CLOCK_LAYOUT_CHANGED` 或 `EVENT_CLOCK_TIME_FORMAT_CHANGED` |
| 背景 | `set_bg_mode` / `set_bg_url` / `set_bg_color` / `set_bg_refresh_s` / `clock_bg_reload` | `EVENT_CLOCK_BG_CHANGED`（仅 bg_mode==2/3） |
| 行情 | `set_quotes_sym_l` / `set_quotes_sym_r` / `set_quotes_refresh_s` / `set_quotes_up_rgba` / `set_quotes_down_rgba` | `EVENT_QUOTES_CHANGED` |
| 显示 | `set_lang` / `set_brightness` / `set_dim_off` / `set_show_fps` / `set_audio_enable` / `set_audio_volume` / `set_theme` | `EVENT_BACKLIGHT_CHANGED` / `EVENT_SHOW_FPS_CHANGED` / `EVENT_AUDIO_VOLUME_CHANGED` |
| 时间 | `set_tz_idx` / `set_hour24` / `set_date_fmt` | `EVENT_CLOCK_TIME_FORMAT_CHANGED` |
| WiFi | `set_wifi_autoconnect` / `set_last_ssid`（配网凭证立即 flush 落盘） | 连接动作由调用方执行 `wifi_connect()` |

> **2026-08 更新**：`app_cfg_bg_fetch_now()` 已删除（WebUI 改直接调 `bg_fetcher_ensure()`）；`app_cfg_wifi_connect_save()` 已删除（config 不指挥业务，调用方改 `app_cfg_set_last_ssid()` + `wifi_connect()`）。

#### 持久化机制

- **NVS 初始化**：`nvs_flash_init()` 失败回退到 `nvs_flash_erase() + nvs_flash_init()`
- **CRC32**：未实现
- **Debounce（C1 已实现）**：`cfg_mark_dirty()` 置脏 + 1s esp_timer 统一写盘，高频 setter 只标记不每次 commit；`app_cfg_flush()` 供关机/配网/手动保存立即落盘
- **版本迁移**：`CFG_VERSION = 8`，加载时若版本旧于 8 调用 `cfg_migrate()`（v8 合并老 config 系统字段，升级即重置旧 `"nasmon"` 配置）
- **校验**：`cfg_validate()` 始终执行范围裁剪（时区/日期/主题/音量/字号/RGBA 透明度等）

### 3.2.5 客户端状态机

各 client 内部维护状态机，每次 `poll()` 推进一个状态，分摊多次 HTTP 往返到多个 poll 周期：

| Client | 状态序列 |
|--------|---------|
| `truenas_client` | `IDLE → FETCH_SYSTEM → FETCH_POOLS → FETCH_DISKS → FETCH_INTERFACES → DONE` |
| `qnap_client` | `IDLE → LOGIN → FETCH_SYSINFO → FETCH_STORAGE → FETCH_DISKS → FETCH_NETWORK → DONE` |
| `netdata_client` | `IDLE → FETCH_CPU → FETCH_RAM → FETCH_NETWORK → FETCH_STORAGE → DONE` |
| `snmp_client` | `IDLE → QUERY_SYSNAME → QUERY_UPTIME → QUERY_CPU → QUERY_IF_IN → QUERY_IF_OUT → WAIT_RESPONSE → DONE` |
| `serial_client` | `IDLE → WAITING_FRAME → RECEIVING → PARSING → DONE`（被动接收） |
| `api_client` | `IDLE → REQUESTING → PARSING → DONE`（单次 GET） |
| `synology_client` | 无显式 enum 状态机，poll 内 SID 登录后同步顺序调用多步 HTTP（真实实现） |
| `unraid_client` | 无多步状态机，单次 GraphQL 查询后 cJSON 解析（真实实现） |
| `mock_client` | 无状态机，每次 poll 直接生成 |

### 3.2.6 通用客户端机制

所有 HTTP 客户端共享：
1. `init`：从 `g_config` 拷贝 IP/端口/凭证，分配 HTTP 缓冲
2. `connect`：尝试首次登录或 `fetch_all`，成功置 `is_online=true`
3. `poll`：
   - 计算轮询间隔 `g_config.poll_sec * 1000` ms
   - 若 `consecutive_failures > 0`，按 `interval * (1 << min(failures,3))` 指数退避，上限 60s
   - 未到间隔直接返回 false
   - 离线则先重连，重连失败 `consecutive_failures++`
   - 按状态机推进一次 fetch，成功后 `consecutive_failures=0` + `is_online=true` + `has_update=true`
4. `disconnect`：清状态、关 socket、释放 HTTP client
5. `destroy`：释放 http_buf + priv + self

### 3.2.7 nas_event_loop 数据循环

路径：[nas_event_loop.c](../main/data/nas_event_loop.c)

启动任务 `task_nas_data_loop`（8KB 栈，优先级 1）：

```c
while (s_running) {
    event_bus_receive(&evt, portMAX_DELAY);   // 阻塞等事件
    xSemaphoreTake(s_fetch_mutex, portMAX_DELAY);
    switch (evt.id) {
        case EVENT_TRIGGER_HTTP_FETCH:
            if (s_fetch_enabled) data_source_fetch_and_publish();
            break;
        case EVENT_WIFI_CONNECTED:    s_fetch_enabled = true;  break;
        case EVENT_WIFI_DISCONNECTED:
        case EVENT_HTTP_STOP:         s_fetch_enabled = false; break;
    }
    xSemaphoreGive(s_fetch_mutex);
}
```

`data_source_fetch_and_publish()`：检查连接 → `data_source_poll()` → poll 成功且 `is_online` → `event_bus_publish_nas_data(data)`。

API：

### 3.3.2 event_bus 详解

详见 [事件总线与数据流](06-事件总线与数据流.md)。

```c
// 核心 API
void event_bus_init(void);                                              // 初始化 mutex + 队列 + 心跳定时器
void event_bus_publish(event_id_t id, const void *data, size_t len);    // 同步扇出订阅 handler + 异步入队
void event_bus_publish_nas_data(const NasData *data);                   // 同步 handler + 异步入队
bool event_bus_receive(event_t *evt, uint32_t timeout_ms);              // 阻塞取事件
void event_bus_subscribe(event_id_t id, event_handler_t cb, void *ud);  // 注册 handler，publish 时同步调用
const char* event_bus_name(event_id_t id);                              // 事件名查询
```

> **2026-08 更新**：修复 `event_bus_subscribe` 失效 bug——`event_bus_publish` 现与 `publish_nas_data` 一致，入队前**同步扇出**给订阅的 handler。此前仅入队不调用 handler，导致 WiFi 事件驱动的 UI 屏刷新（`s_on_wifi_event`）从不执行。

约束：
- `MAX_HANDLERS_PER_EVENT = 8`（超限静默丢弃）
- `EVENT_QUEUE_LEN = 16`（硬编码）
- 不支持 ISR 上下文
- 仅精确事件 ID 匹配（无通配符）
- 单一全局事件总线（不支持多实例）

### 3.3.3 hw_init 详解

详见 [系统架构 § 启动流程](02-系统架构.md#启动流程)。

API：
```c
void hw_init(void);                              // 9 步硬件初始化
void system_monitor_start(void);                 // 启动 2 秒心跳任务
void system_time_init(void);                     // RTC → 系统时钟 + 时区应用
```

`system_time_init()` 关键逻辑：读 RTC 时间 → 与 `BUILD_EPOCH_UTC` 比较 → 若 RTC 早于构建时间则用构建时间重写 RTC（避免断电后时间倒退）→ `settimeofday()` → `tz_apply_current()` 应用时区。

### 3.3.4 bg_fetcher 详解

仅在 `g_cfg.bg_mode == 2` 且 `bg_url` 非空时工作。

```c
void bg_fetcher_ensure(void);   // 启动任务或唤醒已存在任务
```

任务关键设计：
- 栈 6KB，优先级 4，钉在 Core 0，**栈分配在 PSRAM**
- 等 WiFi 最多 12 秒 + 额外 sleep 2 秒（避免 HTTPS TLS 与 radio_init 的 I2S DMA 描述符争抢内部 RAM）
- 仅接受 `canvas_w × canvas_h × 2` 字节的 RGB565 原始字节序
- 临时文件 `/sdcard/clock_bg.bin.dl` → 校验通过后 `rename` 到 `/sdcard/clock_bg.bin`
- 完成后 `event_bus_publish(EVENT_CLOCK_BG_CHANGED, NULL, 0)`

### 3.3.5 nas_event_loop 拉取定时器（原 http_timer）

> 原独立 `http_timer` 模块已并入 `nas_event_loop`，职责归位到 NAS 数据采集模块。

```c
void nas_event_loop_timer_init(void);
void nas_event_loop_timer_start(void);              // 启动 2 秒周期定时器
void nas_event_loop_timer_stop(void);
void nas_event_loop_timer_set_interval_ms(uint32_t ms);
uint32_t nas_event_loop_timer_get_interval_ms(void);
bool nas_event_loop_timer_is_running(void);
```

回调只做一件事：`event_bus_publish(EVENT_TRIGGER_HTTP_FETCH, NULL, 0)`。`dispatch_method = ESP_TIMER_TASK`、`skip_unhandled_events = true`，避免积压。实际抓数由 `task_nas_data_loop` 执行，网络阻塞不会卡住 esp_timer 任务。

### 3.3.8 i18n 详解

支持 4 语种：`0=English`、`1=中文`、`2=日本語`、`3=한국어`。共 57 个翻译 key。

```c
const char* tr(i18n_key_t key);        // 取当前语言字符串
uint8_t i18n_lang(void);                // 读 g_cfg.lang
void i18n_set_lang(uint8_t idx);        // 写 g_cfg.lang（不实时刷新已有标签）
const lv_font_t* i18n_font(void);       // 英文返回 Montserrat 14；CJK 返回 RAM 副本（含 fallback）
void tz_apply_current(void);            // 从 g_cfg.tz_idx 取 POSIX TZ → setenv + tzset
const char* tz_current_city_name(void); // 当前城市友好名
```

字体策略：英文用纯 Latin Montserrat 14；CJK 用 `font_cjk_14` 32k 字形表，经 RAM 副本挂载 Latin fallback（flash 中的 const 字体不能写 fallback 字段，会触发 cache panic）。

### 3.3.9 theme 详解

三套调色板，按 `g_cfg.theme` 切换：

| theme | 名称 | 特征 |
|-------|------|------|
| 0 | Dark | 黑底白字，菜单深灰渐变 |
| 1 | Light | 浅灰底深字，菜单浅灰 |
| 2 | High Contrast | 纯黑底 + 亮黄字，状态色极致对比 |

`theme_palette_t` 含 14 个字段：`bg / text / menu_surf / menu_hdr / menu_btn / sunmap_water_n / sunmap_water_d / sunmap_land_n / sunmap_land_d / ok / warn / danger / info / dim`。

### 3.3.10 landmask / tz_cities

- **landmask.h**：640×172 位图，1bpp MSB-first，`bit=1` 表示陆地。由 `scripts/gen_landmask.py` 从 Natural Earth 1:110m 数据生成。被日照图绘制函数使用（仅在 `bg_mode == 0` 时）。
- **tz_cities.h**：126 城市 / 6 大洲时区表，由 `scripts/gen_tz.py` 生成。结构 `{ name, zone, posix_tz }`，默认城市索引 44（Singapore）。

### 3.4.4 ui_event_loop 任务

独立 FreeRTOS 任务（"ui_event_loop"，8KB 栈，优先级 1），由 `ui_events_start()` 创建：

```c
while (s_running) {
    event_bus_receive(&evt, portMAX_DELAY);
    switch (evt.id) {
        case EVENT_NAS_DATA_UPDATE:    UI_UPDATE(on_nas_data_update_evt(data)); break;
        case EVENT_WIFI_CONNECTED:     UI_UPDATE(on_wifi_state_changed(true));  break;
        case EVENT_WIFI_DISCONNECTED:  UI_UPDATE(on_wifi_state_changed(false)); break;
        case EVENT_BACKLIGHT_CHANGED:  if (dim==0) backlight_apply(bri);        break;
        case EVENT_SHOW_FPS_CHANGED:   show/hide FPS label;                     break;
        case EVENT_TILE_CHANGED:       lv_obj_set_tile_id(...);                 break;
        case EVENT_DISK_CONFIG_CHANGED: rebuild Overview + Storage;             break;
        case EVENT_CFG_CHANGED:        if BG_MODE/BG_URL && bg_mode==2: bg_fetcher_ensure(); break;
    }
}
```

`UI_UPDATE(code)` 宏：`lvgl_lock(50)` → 执行 code → `lvgl_unlock()`，保证 LVGL 调用线程安全。

### 3.4.8 UI 与 nas_event_loop 交互

UI 不直接调用 `nas_event_loop_*` API，全部通过事件总线：

```
nas_event_loop → event_bus_publish_nas_data(data) → task_ui_event_loop 收到 → on_nas_data_update_evt(data) → 各 *_screen_update_* 函数
```

`on_nas_data_update_evt` 按 `data->is_online` 分支：
- Overview：CPU% / CPU 温度 / 内存% / 磁盘% / 各 HDD LED（颜色按 health 0/1/2）+ 名称
- Storage：各 HDD 名称 / 用量条（着色按 health）/ 温度 / 在线状态
- 网络：仅当 tx/rx 速率变化 >= 0.05 Mbps 时才刷新（避免高频抖动）

阈值去抖：`THRESHOLD_CPU=2` / `THRESHOLD_TEMP=1` / `THRESHOLD_MEM=2` / `THRESHOLD_DISK=1`，差值超过阈值才刷新 UI。

### 3.4.9 命名约定

EEZ-Generator 风格：
- 屏幕对象：`ui_Screen_<Name>`（全局）
- Settings 父屏控件：`ui_Settings_<Widget>`（全局）
- Tab 容器：`ui_Settings_Tabpage_<tab>`（全局）
- Tab 内控件：WifiTab 用全局 `ui_Settings_<Widget>_<Name>`；其他 Tab 多用文件 static
- 事件回调：`ui_event_<Screen>_<Widget>` 或 `ui_event_<Screen>_<gesture>`
- 更新 API：`<screen>_screen_update_<field>`（如 `overview_screen_update_cpu`）

### 3.4.10 资源管理（cleanup）

每个 Screen 提供成对 `*_init()` / `*_destroy()` 或 `*_cleanup()`：

- **懒加载 + 幂等 init**：所有 `*_screen_init` 入口先检查全局对象是否已非 NULL
- **destroy 对称性**：init 创建什么，destroy 就删除什么并置 NULL；Settings 父屏 destroy 级联所有子 Tab cleanup
- **事件订阅清理**：WifiTab 与 WifiConfig 在 cleanup 时**必须 unsubscribe**，否则回调指向已释放控件造成 UAF
- **定时器清理**：Boot 删 3 个定时器；WifiConfig 删 `s_wifi_status_timer`；dim_timer / time_timer 跨 Screen 不删
- **`memset(&s_screen, 0, ...)`**：Overview/Storage 用 memset 清空 struct（含控件指针 + last_values 缓存）
- **磁盘配置变更触发全屏重建**：`EVENT_DISK_CONFIG_CHANGED` → Overview + Storage destroy + init
