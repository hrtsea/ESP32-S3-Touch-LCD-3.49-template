# 6. 事件总线与数据流

## 6.1 设计概述

项目自研轻量事件总线，采用 **同步+异步双路径** 设计：

| 路径 | 函数 | 行为 |
|------|------|------|
| **异步（默认）** | `event_bus_publish(id, data, len)` | 构造 `event_t` 投递到 FreeRTOS 队列 `s_event_queue`（长度 16，非阻塞 `xQueueSend(...,0)`） |
| **同步+异步混合** | `event_bus_publish_nas_data(data)` | 先把 `NasData` `memcpy` 进 mutex 保护的 `s_nas_data_buffer`（并补写 `disk_slot_count`），**同步**调用所有已注册 handler，**再**异步入队 |
| **消费** | `event_bus_receive(evt, timeout)` | 阻塞式从队列取事件 |

文件：[event_bus.c](../main/utils/event_bus.c) / [event_bus.h](../main/utils/event_bus.h)

## 6.2 事件 ID 一览

```c
typedef enum {
    // 显示/旋转
    EVENT_ROTATION_CHANGED,

    // WiFi 状态
    EVENT_WIFI_CONNECTED,
    EVENT_WIFI_DISCONNECTED,
    EVENT_WIFI_SCAN_DONE,
    EVENT_WIFI_SCAN_STARTED,

    // WiFi 配网
    EVENT_WIFI_PROVISION_START,
    EVENT_WIFI_PROVISION_STOP,
    EVENT_WIFI_PROVISION_CONFIG_RECEIVED,

    // 配置变更
    EVENT_CFG_CHANGED,              // 载荷: cfg_change_info_t { cfg_field_t field }
    EVENT_DISK_CONFIG_CHANGED,      // 无载荷
    EVENT_STORAGE_CHANGED,

    // 时钟 UI
    EVENT_CLOCK_LAYOUT_CHANGED,
    EVENT_CLOCK_BG_CHANGED,
    EVENT_CLOCK_TIME_FORMAT_CHANGED,
    EVENT_QUOTES_CHANGED,

    // 显示选项
    EVENT_SHOW_FPS_CHANGED,         // 载荷: uint8_t show
    EVENT_BACKLIGHT_CHANGED,        // 载荷: int dim_state 或 uint8_t brightness
    EVENT_TILE_CHANGED,             // 载荷: int tile_idx

    // 音频
    EVENT_AUDIO_PLAY_START,
    EVENT_AUDIO_PLAY_STOP,
    EVENT_AUDIO_RECORD_START,
    EVENT_AUDIO_RECORD_STOP,
    EVENT_AUDIO_VOLUME_CHANGED,     // 载荷: uint8_t volume

    // 用户/定时
    EVENT_USER_ACTIVITY,
    EVENT_TICK_1HZ,                 // 1 秒心跳（无载荷）
    EVENT_TICK_10HZ,                // 100ms 心跳（无载荷）

    // NAS 数据
    EVENT_NAS_DATA_UPDATE,          // 载荷: NasData（同步路径用 mutex buffer，异步路径用队列）
    EVENT_TRIGGER_HTTP_FETCH,       // 无载荷
    EVENT_HTTP_STOP,

    EVENT_ID_MAX,
} event_id_t;
```

可通过 `event_bus_name(id)` 查询事件名字符串，便于日志。

## 6.3 心跳定时器

`event_bus_init()` 启动两个周期 `esp_timer`：

| 定时器 | 周期 | 发布事件 |
|--------|------|---------|
| 1Hz | 1 秒 | `EVENT_TICK_1HZ`（无载荷） |
| 10Hz | 100ms | `EVENT_TICK_10HZ`（无载荷） |

为 UI 提供低成本节拍，无需各自创建定时器。

## 6.4 订阅模式

### 模式 A：专用任务 + 队列接收（推荐）

适合大数据载荷（如 `NasData`）或需要集中处理多类事件的场景。

```c
// 任务循环（典型实现见 ui_events.c::task_ui_event_loop 和 nas_event_loop.c::task_nas_data_loop）
while (s_running) {
    event_t evt;
    event_bus_receive(&evt, portMAX_DELAY);
    switch (evt.id) {
        case EVENT_NAS_DATA_UPDATE:
            // 处理 NasData
            break;
        // ...
    }
}
```

**当前使用方**：
- `task_ui_event_loop`（[ui_events.c](../main/ui/ui_events.c)）：订阅 8 类事件刷新 UI
- `task_nas_data_loop`（[nas_event_loop.c](../main/data/nas_event_loop.c)）：订阅 `EVENT_TRIGGER_HTTP_FETCH` / `EVENT_WIFI_CONNECTED/DISCONNECTED` / `EVENT_HTTP_STOP`

### 模式 B：回调订阅（已废弃，仅轻量场景）

```c
event_bus_subscribe(EVENT_WIFI_CONNECTED, my_handler, user_data);
```

> **注意**：`event_bus_subscribe` 当前实现仅打警告日志，不再注册真正的回调。但 `event_bus_publish_nas_data` 仍然走同步回调路径（内部维护 `s_slots[EVENT_NAS_DATA_UPDATE]`）。

**当前使用方**（已废弃路径，仍可工作但建议迁移）：
- WifiTab：订阅 4 个 WiFi 事件
- WifiConfig：订阅 4 个 WiFi 事件

回调内创建一次性 `lv_timer` 把刷新派发回 LVGL 线程，避免在事件发布者任务上下文直接操作 UI。

## 6.5 典型时序

### 时序 1：NAS 数据刷新

```
[http_timer 2s 周期到期]
   │
   │ event_bus_publish(EVENT_TRIGGER_HTTP_FETCH, NULL, 0)
   │   → xQueueSend(s_event_queue, &evt, 0)
   ▼
[nas_event_loop 任务]
   event_bus_receive(&evt, portMAX_DELAY)   // 唤醒
   xSemaphoreTake(s_fetch_mutex, ...)
   switch (evt.id) {
     case EVENT_TRIGGER_HTTP_FETCH:
       if (s_fetch_enabled) {
         data_source_poll();                // VTable 分发到 client 状态机
         if (data->is_online) {
           event_bus_publish_nas_data(data);
           │
           │ ├─ memcpy 到 s_nas_data_buffer (mutex 保护)
           │ ├─ 同步调用所有 NAS_DATA_UPDATE handler
           │ └─ xQueueSend(s_event_queue, &evt, 0)
           ▼
[ui_event_loop 任务]
   event_bus_receive(&evt, portMAX_DELAY)   // 唤醒
   UI_UPDATE(on_nas_data_update_evt(data))
     │
     │ lvgl_lock(50)
     │ overview_screen_update_cpu(temp/mem/disk/hdd_led/hdd_name/network)
     │ storage_screen_update_hdd_bar/temp/online
     │ lvgl_unlock()
```

### 时序 2：配置变更反馈

```
[UI 滑块拖动 - set_clock_size(3)]
   │
   │ app_cfg_set_clock_size(3)
   │   ├─ g_cfg.clock_size = 3
   │   ├─ cfg_publish(CFG_FIELD_CLOCK_SIZE)
   │   │   → event_bus_publish(EVENT_CFG_CHANGED, &info, sizeof(info))
   │   ├─ event_bus_publish(EVENT_CLOCK_LAYOUT_CHANGED, NULL, 0)  // 衍生事件
   │   └─ app_cfg_save()  // 立即写 NVS
   ▼
[ui_event_loop 任务]
   case EVENT_CFG_CHANGED:
     // 处理 BG_MODE/BG_URL 时触发 bg_fetcher_ensure()
   case EVENT_CLOCK_LAYOUT_CHANGED:
     // ui_clock 重建时钟显示
```

### 时序 3：WiFi 连接状态变化

```
[esp_wifi_config 库内部]
   │ esp_bus_publish(WIFI_CFG_EVT_CONNECTED)
   ▼
[wifi_bridge 回调]
   bridge_forward(EVENT_WIFI_CONNECTED, NULL, 0)
     → event_bus_publish(EVENT_WIFI_CONNECTED, NULL, 0)
   ▼
[多消费者并发]
   ├─ [nas_event_loop] s_fetch_enabled = true
   ├─ [ui_event_loop]  UI_UPDATE(on_wifi_state_changed(true))
   │                     → 刷新 IP 标签 + WiFi 图标颜色
   └─ [WifiTab 回调]   创建 lv_timer → wifi_tab_refresh_status()
   └─ [WifiConfig 回调] 启动 100ms 定时器 → 销毁自身 + 加载 Overview
```

### 时序 4：磁盘配置变更触发全屏重建

```
[NasTab 保存] 
   config_save_disk_config(sata, m2)
     ├─ nvs_set_u8("sata_count", sata)
     ├─ nvs_set_u8("m2_count", m2)
     └─ event_bus_publish(EVENT_DISK_CONFIG_CHANGED, NULL, 0)
   ▼
[ui_event_loop]
   case EVENT_DISK_CONFIG_CHANGED:
     UI_UPDATE({
       ui_Screen_Overview_screen_destroy();
       ui_Screen_Overview_screen_init();      // 重建动态 HDD 控件数组
       ui_Screen_Storage_screen_destroy();
       ui_Screen_Storage_screen_init();
     })
```

### 时序 5：背景图抓取

```
[UI 设置 bg_mode=2]
   app_cfg_set_bg_mode(2)
     └─ cfg_publish(CFG_FIELD_BG_MODE)
   ▼
[ui_event_loop]
   case EVENT_CFG_CHANGED:
     if (field == CFG_FIELD_BG_MODE && g_cfg.bg_mode == 2):
       bg_fetcher_ensure()
         │
         │ xTaskCreatePinnedToCoreWithCaps(bg_fetcher_task, PSRAM 6KB, prio 4, Core 0)
         ▼
[bg_fetcher_task]
   等 WiFi (最多 12s) + sleep 2s
   循环:
     bg_fetch_once(g_cfg.bg_url)
       ├─ HTTP 流式下载到 /sdcard/clock_bg.bin.dl
       ├─ Magic 检测（仅接受 RGB565 原始字节序）
       └─ rename 到 /sdcard/clock_bg.bin
     event_bus_publish(EVENT_CLOCK_BG_CHANGED, NULL, 0)
     │
     ▼
[ui_clock / ui_event_loop]
   case EVENT_CLOCK_BG_CHANGED:
     重新加载 /sdcard/clock_bg.bin 到 canvas
```

## 6.6 约束与注意事项

| 约束 | 说明 |
|------|------|
| `MAX_HANDLERS_PER_EVENT = 8` | 每事件最多 8 个 handler，超过静默丢弃 |
| `EVENT_QUEUE_LEN = 16` | 队列长度硬编码，无独立任务（消费方自带任务） |
| 不支持 ISR 上下文 | 发布函数在定时器/任务上下文调用 `xQueueSend` |
| 仅精确事件 ID 匹配 | 不支持通配符 |
| 单一全局事件总线 | 不支持多实例 |
| `event_t.data` 存储原始指针 | 发布者数据释放后会导致悬空指针（**仅对异步路径**）。NAS 数据走专用 mutex buffer 规避此问题 |
| handler 在发布者任务上下文同步执行 | 若 handler 耗时较长会阻塞发布者（**仅同步路径**） |
