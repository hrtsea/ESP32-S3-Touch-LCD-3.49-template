# 7. 依赖关系

## 7.1 内部模块依赖

下图展示 `main/` 内部各模块的依赖方向（箭头表示"依赖于"）：

```
                    ┌──────────────┐
                    │  main.cpp    │  (入口)
                    └──────┬───────┘
                           │
        ┌──────────────────┼─────────────────────────────┐
        │                  │                              │
        ▼                  ▼                              ▼
   ┌─────────┐      ┌──────────┐                  ┌─────────────┐
   │  ui/    │      │ data/    │                  │  utils/     │
   │ screens │      │ client/  │                  │ event_bus   │
   └────┬────┘      └────┬─────┘                  │ hw_init     │
        │                │                         │ bg_fetcher  │
        │ g_cfg /        │ g_config                │ nas_event_loop │
        │ g_config       │ event_bus               │ wifi_bridge    │
        │ event_bus      │                         │ cli / i18n  │
        │                │                         │ theme       │
        ▼                ▼                         └──────┬──────┘
   ┌────────────────────────────┐                        │
   │       config/              │◄───────────────────────┘
   │  app_cfg  config  app_info │  (g_cfg / g_config 全局实例)
   └────────────────────────────┘
        │
        ▼
   ┌────────────────────────────┐
   │  components/ (BSP)         │
   │  i2c_bsp / lcd_bl_pwm_bsp  │
   │  adc_bsp / button_bsp      │
   │  audio_min / i2c_equipment │
   │  lvgl / SensorLib          │
   └────────────────────────────┘
        │
        ▼
   ┌────────────────────────────┐
   │  ESP-IDF + managed_comp.   │
   └────────────────────────────┘
```

### 关键依赖规则

| 规则 | 说明 |
|------|------|
| UI 层不直接调用 BSP | 通过 `event_bus_receive()` 接收数据，通过 `app_cfg_*` / `config_*` 读写配置 |
| 数据层不直接调用 UI | 通过 `event_bus_publish_nas_data()` 通知 UI |
| 配置层不直接引用 UI/LVGL | 通过 `event_bus_publish()` 发布事件 |
| `bg_fetcher` 不 include UI 头文件 | 通过 `EVENT_CLOCK_BG_CHANGED` 通知 UI |
| 组件层禁止修改 | 通过头文件暴露 API 供上层调用 |

## 7.4 编译排除清单

文件：[CMakeLists.txt](../CMakeLists.txt#L10)

```cmake
set(EXCLUDE_COMPONENTS audio_bsp codec_board espressif__esp_codec_dev)
```

排除原因：IDF 5.2.x 上 `esp_codec_dev` 依赖 legacy `driver/i2c.c` 构造器，与新版 `i2c_master` 驱动冲突，会在启动时 abort。`audio_bsp` 和 `codec_board` 依赖 `esp_codec_dev`，因此一并排除。

**注意**：`audio_min` 组件 `PRIV_REQUIRES esp_codec_dev`，但实际通过 `radio` 组件间接使用 `esp_codec_dev`，因此 `esp_codec_dev` 被排除后 `audio_min` 仍可编译（链接时通过 `radio` 的符号解析）。

## 7.5 IDF 版本约束

- **ESP-IDF**：v5.5.4（项目使用 `i2c_master` 新驱动，要求 IDF ≥ 5.2）
- **`idf_component.yml` 声明**：`idf: version: '>=4.1.0'`（声明宽松，但实际需要 ≥ 5.5.4）
- **mbedtls**：组件包含
- **编译选项**：`-Wno-error=stringop-truncation`（顶层 CMakeLists.txt 强制设置，避免字符串截断警告导致编译失败）

## 7.6 链接器特殊处理

文件：[main/CMakeLists.txt](../main/CMakeLists.txt#L96-L99)

```cmake
# 强制链接器包含 radio 和 recorder 归档的全部符号
# (webui 引用它们，但链接顺序无法解析依赖)
idf_build_set_property(LINK_OPTIONS "-Wl,--whole-archive" APPEND)
idf_build_set_property(LINK_OPTIONS "esp-idf/radio/libradio.a" APPEND)
idf_build_set_property(LINK_OPTIONS "esp-idf/recorder/librecorder.a" APPEND)
idf_build_set_property(LINK_OPTIONS "-Wl,--no-whole-archive" APPEND)
```

## 7.8 数据源客户端依赖

每个 client 实现独立，但共享：
- `data_source.h` 的 VTable 接口
- `nas_data.h` 的数据模型
- `config.h` 的 `g_config`（IP/端口/凭证）
- `event_bus.h`（通过 `nas_event_loop` 间接使用）
- `app_info.h` 的容量上限常量

| Client | 额外依赖 |
|--------|---------|
| `synology_client` | `esp_http_client` + cJSON |
| `qnap_client` | `esp_http_client` + cJSON + 自写 XML 解析 |
| `truenas_client` | `esp_http_client` + cJSON |
| `netdata_client` | `esp_http_client` + cJSON |
| `snmp_client` | lwIP socket（UDP） + 自写 BER/ASN.1 |
| `serial_client` | `driver/uart` |
| `api_client` | `esp_http_client` + cJSON |
| `mock_client` | `math.h`（sinf） |
