# 9. 约束与已知问题

## 9.1 硬性约束（不可违反）

> 本节约束来自项目 `project_memory.md`，是开发时必须遵守的强制规则。

### 编译与构建

| 约束 | 说明 |
|------|------|
| `-Wno-error=stringop-truncation` | 强制忽略字符串截断警告（顶层 CMakeLists.txt） |
| 排除 `audio_bsp` / `codec_board` / `espressif__esp_codec_dev` | 因 IDF 5.2+ i2c 驱动冲突 |
| 排除 `gmf_io` / `gmf_core` / `gmf_audio` | 因 i2s_pdm.h 兼容性问题 |
| `CONFIG_WIFI_CFG_HTTP_MAX_URI_HANDLERS = 64` | 容纳 27 esp_wifi_config handlers + ~10 webui routes |
| `idf_component.yml` 必须位于 `main/` 目录 | |
| ESP-IDF ≥ 5.4 | esp_wifi_config AI 集成指南要求 |
| 不允许修改 `components/` 目录代码 | |

### 硬件与驱动

| 约束 | 说明 |
|------|------|
| I2S TX 与 RX 必须使用相同采样率 | TDM 模式共享 BCLK/WS 时钟 |
| DMA 缓冲必须位于内部 RAM | 不能用 PSRAM，且需 4 字节或 32 字节对齐 |
| `LVGL_DMA_BUFF_LEN` = `EXAMPLE_LCD_H_RES × LVGL_FLUSH_STRIP_ROWS × 2` | 128 行 stripe × 172 宽 × 2 字节 |
| LVGL 刷新周期通过 `CONFIG_LV_DISP_DEF_REFR_PERIOD` 配置 | 当前 15ms（~66 FPS） |
| I2C 触摸读取必须由独立任务处理 | 优先级 5（高于 LVGL 任务优先级 4） |
| `lvgl_touch_cb` 仅从缓存读触摸数据 | mutex 保护，不执行直接 I2C 操作 |

### 配置访问

| 约束 | 说明 |
|------|------|
| `g_cfg` 必须用 `cfg_lock()` / `cfg_unlock()` 保护 | 防止跨任务数据竞争 |
| 字符串字段（`last_ssid` / `clock_text` / `bg_url` / `quotes_sym_l/r`）的跨任务读写 | 通过 `s_cfg_mutex` 互斥锁 |
| 配置层不得直接引用 UI/LVGL 组件 | 通过 `event_bus_publish()` 通知 |
| 所有 `app_cfg_set_*` 必须走三阶段流程 | 验证 → 内存更新 → 事件发布 + 持久化 |
| 滑块拖动事件只更新 `g_cfg` 内存 | 释放时才持久化到 NVS |
| WiFi 凭证使用两阶段提交 | pending 凭证存静态变量，连接成功后才写 NVS |
| NVS 写使用 1 秒 debounce + 增量字段更新 | 减少 flash 磨损（**注：当前实现未真正 debounce**） |
| 硬盘数量 `sata_disk_count + m2_disk_count` ≤ `MAX_DISKS` (16) | 编译时常量 |
| 硬盘配置修改后必须发布 `EVENT_DISK_CONFIG_CHANGED` | UI 监听并自动刷新 Overview + Storage |
| NAS 配置必须使用线程安全 getter/setter | mutex 保护 |
| NAS 配置变更必须发布事件 + 持久化到 NVS | 带 debounce |
| NVS key 使用短而一致的命名 | 如 `n_type` / `n_ip` |
| NAS 配置和 app 配置存储在独立 NVS 命名空间 | `"nas"` 和 `"app"`（**实际项目用 `"nasmon"` 和 `"cfg"`**） |
| 日期格式使用 `date_fmt_t` 枚举 | `DATE_FMT_ISO=0` / `DATE_FMT_DD_MM=1` / `DATE_FMT_MM_DD=2`，`DATE_FMT_MAX=2` |
| 日期分隔符统一为 `'.'` | 不是 `'/'` |

### 事件总线

| 约束 | 说明 |
|------|------|
| `event_t.data` 存储原始指针 | 发布者数据释放后会导致悬空指针（仅异步路径；NAS 数据走专用 mutex buffer 规避） |
| handler 在发布者任务上下文同步执行 | 耗时较长会阻塞发布者 |
| `MAX_HANDLERS_PER_EVENT = 8` | 超过静默丢弃 |
| 不支持 ISR 上下文调用 | |
| 仅支持精确事件 ID 匹配 | 不支持通配符 |
| 单一全局事件总线 | 不支持多实例 |
| 队列长度硬编码为 16 | 无独立任务 |

### WiFi 与配网

| 约束 | 说明 |
|------|------|
| 必须使用 `esp_wifi_config` 库 | 删除原有 WiFi 接口 |
| 事件订阅必须在 `wifi_cfg_init()` 之前 | 避免错过初始事件（`esp_bus_sub()` 先于 `wifi_cfg_init()`） |
| Network Provisioning BLE 与 Improv BLE 互斥 | 不能同时编译 |
| `WIFI_PROV_ALWAYS` 和 `WIFI_ON_RECONNECT_EXHAUSTED_PROVISION` 禁用 | BLE 栈冲突，改用 `WIFI_PROV_ON_FAILURE` 或 `WIFI_PROV_MANUAL` |
| 传入现有 HTTP 服务器时库仅注册/注销路由 | 不创建/销毁服务器 |
| `esp_wifi_config` 默认网络仅在首次启动时写 NVS | 后续修改需 API/配网接口 |
| 自定义变量上限 `CONFIG_WIFI_CFG_MAX_VARS` | 默认 10 |
| 配网模式必须为 `WIFI_PROV_ON_FAILURE` | 手动配网触发按钮 |
| HTTP Basic Auth 必须启用 | esp_wifi_config API 端点 |
| WiFi 扫描必须非阻塞 | 防止 LVGL 渲染卡顿 |
| WiFi 连接尝试必须先断开现有连接 | 等 100ms 再设置新配置 |
| `esp_wifi_disconnect()` 返回值必须检查 | 错误处理 |
| `g_wifi_connected` 全局变量不得由 UI 模块直接修改 | 依赖 WiFi 事件处理器 |
| WiFi 连接开始时间 `g_wifi_connect_started_ms` | 连接成功时必须重置 |
| WiFi 扫描按钮必须使用 static timer handle | 防止多个定时器实例和内存泄漏 |
| 扫描刷新列表逻辑必须抽取公共函数 | 消除重复代码 |

## 9.2 工程约定

### 代码组织

- 主应用代码位于 `main/` 目录
- 本地组件在 `components/` 目录（14 个）
- 外部依赖在 `managed_components/`（12 个，由 `idf_component.yml` 控制）
- 构建依赖通过 `main/CMakeLists.txt`（本地）和 `idf_component.yml`（外部）控制

### UI 模块重构模式

参考 [SQUARELINE_SPEC.md](../SQUARELINE_SPEC.md)。要点：
- 命名：所有导出对象统一为 `ui_<ScreenName>_<WidgetName>`，事件回调为 `ui_event_<ScreenName>_<WidgetName>`
- TileView 适配：`ui_<Screen>_create(parent)` 接收 parent，`*_cleanup()` 替代 `*_delete()`
- .h 文件四区分区：对象声明 / 控件声明 / 事件回调声明 / 创建清理函数声明
- .c 文件五区分区：对象定义 / 静态样式 / 事件回调 / create / cleanup
- 样式管理：固定样式用 `lv_style_t` 抽取为静态变量；与主题/语言/运行时相关的样式保留行内
- 内部子控件不暴露为全局变量，通过 `lv_obj_get_child` 访问

### 数据源模式

- 使用 C 语言 VTable 模式模拟多态，定义在 `data_source.h`
- 数据源实例通过 `data_source_create()` 工厂函数创建
- 每个数据源客户端实现内部状态机，分步数据获取 + 指数退避

### UI 设置修改流程

- 所有 UI 设置修改必须通过 `app_cfg_set_*` API
- 直接修改 `g_cfg` 禁止
- 每个 `app_cfg_set_*` 函数三阶段：验证 → 内存更新 → 事件发布 + 持久化
- 滑块拖动事件只更新 `g_cfg` 内存，释放时才持久化
- 配置变更通过 `event_bus` 通知，不使用直接回调
- `ui_clock` 在 `create()` 订阅事件，在 `cleanup()` 取消订阅

### 配置分层管理

- 配置按功能分层：`app_cfg`、`wifi_cfg`、`nas_cfg` 等
- 使用独立 NVS 命名空间
- 配置模块公共工具（NVS 操作、CRC 校验、版本管理）应抽象到 `cfg_common.c/h`

## 9.3 已知问题与改进建议

### 配置层

| 问题 | 影响 | 建议 |
|------|------|------|
| `app_cfg_flush()` 声明未实现 | 关机/重启路径若依赖此函数会链接失败 | 补全实现或移除声明 |
| `on_wifi_connected_evt` 前向声明未定义 | 历史遗留 | 清理 |
| `app_cfg_save()` 注释说"增量"实际全量写 | flash 寿命 + UI 卡顿 | 实现真正的脏字段追踪 + debounce |
| 缺 CRC / magic | NVS 损坏只能靠范围裁剪兜底 | 加 magic + CRC32 校验 |
| 双备份策略不完整 | `ConfigBackup` 仅覆盖 NAS/SNMP/串口子集，且仅内存态 | 扩展到全字段 + NVS 备份分区 |
| 双 NVS 初始化潜在竞争 | `app_cfg_init()` 与 `config_load()` 都调用 `nvs_flash_init()` | 在 `main.cpp` 明确调用顺序并加防护 |
| Getter 返回内部指针 | `app_cfg_get_clock_text` / `_bg_url` / `_quotes_sym_l/r` 非线程安全 | 改为 `size_t app_cfg_get_xxx(char* buf, size_t len)` 模式 |
| 两套命名空间风格不统一 | `"cfg"` vs `"nasmon"`，key 短缩写 vs 全描述性 | 长期统一 |
| `app_cfg_save()` 头注释与实现不一致 | 误导维护者 | 修正注释或实现 |

## 9.4 Lessons Learned

> 来自项目历史踩坑记录，供后续开发参考。

### 触摸与 LVGL

- 同步 I2C 触摸读取在 `lvgl_touch_cb` 中导致 LVGL 任务每 tick 阻塞 1-2ms → 独立任务 + 缓存数据解决
- LVGL 内建 FPS 监控只计 >5000 像素的帧 → 项目自定义 FPS 计数所有 `disp_driver_flush()` 完成
- `lvgl_touch_cb` 优先级必须高于 LVGL 任务（5 > 4）

### WiFi

- 连接尝试期间（sta is connecting）发起新连接导致 `ESP_ERR_WIFI_STATE` → 必须先断开 + 等稳定
- 认证失败 reason=201：连接状态在 IP 获取前被错误报告为已连接
- DNS 解析失败：WiFi 关联后立即发起网络请求（IP 未获取）→ 等 `EVENT_WIFI_CONNECTED`
- WiFi 扫描阻塞 HTTP 服务器 → 加 `isScanning` 标志暂停状态轮询
- 扫描按钮重复创建定时器 → 用 static timer handle
- 扫描完成应自动刷新状态 + 网络列表，保持 UI 一致性
- 用户应被告知扫描时长（"Scanning... (may take 10+ seconds)"）

### 配置

- 硬盘数量配置必须验证 ≤ `MAX_DISKS`
- `EVENT_DISK_CONFIG_CHANGED` 实现后，用户修改硬盘数量无需重启即可自动刷新 UI

### HTTP 与定时器

- HTTP 处理函数中直接调 `httpd_stop()` 会导致死锁 → 先发响应再异步触发
- 定时器服务任务栈空间不足（2-4KB）执行 `httpd_stop()` / `esp_wifi_stop()` 会栈溢出 → 改用独立任务 + 6KB+ 栈

### 配网

- `WIFI_PROV_ALWAYS` 和 `WIFI_ON_RECONNECT_EXHAUSTED_PROVISION` 因 BLE 栈冲突禁用
- Network Provisioning BLE 与 Improv BLE 不能同时使用
- 事件订阅必须在 `wifi_cfg_init()` 之前
- 传入现有 HTTP 服务器需手动管理；库仅处理路由注册
- `esp_wifi_config` 默认网络仅首次启动写 NVS；后续修改需 API/配网接口
- `with_webui_customize` 示例不推荐用于本项目（功能限制）
