# 2. 系统架构

## 2.1 分层架构

项目采用清晰的 5 层架构，自底向上依次为：

```
┌─────────────────────────────────────────────────────────────┐
│                  UI 层 (main/ui/)                           │
│   LVGL 屏幕 + 控件 + 事件回调 + UI 状态管理                  │
│   ui_Screen_Boot / Overview / Storage / Settings / WifiConfig│
└───────────▲───────────────────────────────▲─────────────────┘
            │ event_bus_receive              │ app_cfg_get_*
┌───────────┴─────────────────┐  ┌───────────┴──────────────┐
│    工具层 (main/utils/)     │  │   配置层 (main/config/)   │
│  event_bus / hw_init /      │  │  app_cfg + fan_config +  │
│  bg_fetcher / wifi_bridge / │  │  app_info (单一配置系统)  │
│  wifi_bridge / cli / i18n / │  │  NVS 持久化 + 事件发布     │
│  theme / landmask / tz      │  └───────────▼──────────────┘
└───────▲─────────▲──────────┘              │ g_cfg (全局实例)
        │         │                          │
        │         │ ┌────────────────────────┴──────────────┐
        │         │ │       数据层 (main/data/)             │
        │         │ │ data_source VTable + 工厂 + 8 客户端   │
        │         │ │ nas_event_loop / nas_data_json        │
        │         │ └───────────────▲───────────────────────┘
        │         │                 │ data_source_poll()
        │         │                 │ event_bus_publish_nas_data()
        │         │                 │
┌───────┴─────────┴─────────────────┴─────────────────────────┐
│                   组件层 (components/)                       │
│  i2c_bsp / lcd_bl_pwm_bsp / adc_bsp / button_bsp /          │
│  audio_min / i2c_equipment (SensorLib) / lvgl               │
└───────▲─────────────────────────────────────────▲───────────┘
        │                                           │
┌───────┴───────────────────────────────────────────┴─────────┐
│              ESP-IDF + managed_components                    │
│  esp_wifi / esp_http_server / esp_lcd / esp_codec_dev /      │
│  esp_wifi_config / esp_io_expander_tca9554 / esp_lcd_axs15231b│
└─────────────────────────────────────────────────────────────┘
```

### 层间依赖原则
- **UI 层**：不直接调用硬件 BSP；通过 `event_bus_receive()` 接收数据，通过 `app_cfg_*` / `config_*` API 读写配置。
- **数据层**：不直接调用 UI 函数；通过 `event_bus_publish_nas_data()` 通知 UI。
- **配置层**：不直接引用 UI/LVGL；通过 `event_bus_publish()` 发布 `EVENT_CFG_CHANGED` 等事件。
- **工具层**：`bg_fetcher` 通过事件总线通知 UI（不 include UI 头文件）；`hw_init` 是硬件初始化总入口。
- **组件层**：禁止修改；通过头文件暴露 C/C++ API 供上层调用。

## 2.2 启动流程

入口函数 [`app_main()`](../main/main.cpp#L111)，启动顺序：

```
app_main()
  │
  ├─ 1. log_init()                    # 日志级别
  ├─ 2. event_bus_init()              # 事件总线 + 1Hz/10Hz 心跳定时器
  ├─ 3. app_cfg_load()                # NVS 加载 g_cfg (命名空间 "cfg")
  ├─ 4. hw_init()                     # 9 步硬件初始化
  │     ├─ [1/9] i2c_master_Init()    # I2C0 (RTC+IMU) + I2C1 (Touch)
  │     ├─ [2/9] TCA9554 IO 扩展       # 拉高 P6/P7 电源轨
  │     ├─ [3/9] lcd_bl_pwm_bsp_init() # 背光 PWM (从 g_cfg.brightness)
  │     ├─ [4/9] disp_driver_init()   # LCD 面板 + LVGL + 触摸任务
  │     ├─ [5/9] i2c_rtc_setup() + i2c_imu_setup()
  │     ├─ [6/9] adc_bsp_init()       # 电池电压采集
  │     ├─ [7/9] audio_min_init()     # ES8311 + I2S TDM + 音量
  │     ├─ [9/9] _sdcard_init() + button_Init()
  │     └─ system_time_init()         # RTC → 系统时钟 + 时区应用
  │
  ├─ 5. network_init()
  │     ├─ esp_bus_init()             # esp_wifi_config 库事件总线
  │     ├─ wifi_cfg_init(&cfg)        # WiFi 配网 + SoftAP + REST API
  │     ├─ wifi_bridge_init()         # esp_bus → 项目 event_bus 桥接
  │     ├─ webui_set_auth()           # WebUI Basic Auth
  │     └─ webui_start_with_httpd()   # 共享 wifi_cfg 的 HTTP 服务器
  │
  ├─ 6. nas_event_loop_start()        # NAS 数据循环任务 (8KB 栈, 优先级 1)
  ├─ 7. nas_event_loop_timer_init/start() # 2 秒周期触发 EVENT_TRIGGER_HTTP_FETCH（原 http_timer）
  ├─ 8. ui_init()                     # LVGL 锁 + FPS 标签 + Boot 屏 + 后台抓取
  ├─ 9. cli_start()                   # USB-Serial-JTAG REPL
  └─ 10. system_monitor_start()       # 2 秒心跳 (堆内存 + FPS 监控)
```

启动进度通过 `status_text_append()` 写入 UI 状态栏，Boot 屏进度条同步推进 25/50/75/100。

## 2.3 线程模型

项目运行时存在多个 FreeRTOS 任务：

| 任务名 | 栈 | 优先级 | 核心 | 来源 | 职责 |
|--------|-----|--------|------|------|------|
| `nas_data_loop` | 8KB | 1 | 任意 | `nas_event_loop.c` | 阻塞等事件，触发 NAS 数据拉取 |
| `ui_event_loop` | 8KB | 1 | 任意 | `ui_events.c` | 阻塞等事件，刷新 UI 控件 |
| `bg_fetcher` | 6KB | 4 | Core 0 | `bg_fetcher.c` | 后台下载时钟背景图（栈在 PSRAM） |
| `lvgl_touch` | — | 5 | — | `disp_driver.c` | I2C 触摸读取（优先级高于 LVGL） |
| `lvgl` | — | 4 | — | `disp_driver.c` | LVGL 主循环（渲染 + 事件分发） |
| `radio` | — | — | — | `radio.c` | I2S 音频流播放 |
| `heartbeat` | — | — | — | `hw_init.c` | 2 秒周期堆内存监控 |

### 关键线程安全约束
- **LVGL 调用**：非 LVGL 任务（如 bg_fetcher、wifi_bridge、nas_event_loop）操作 UI 时必须使用 `lvgl_lock(timeout)` / `lvgl_unlock()` 保护。
- **g_cfg 字符串字段**：`last_ssid` / `clock_text` / `bg_url` / `quotes_sym_l/r` 及 NAS/SNMP 凭证字符串的跨任务读写通过 `s_cfg_mutex` 互斥锁保护；调用 `app_cfg_get_last_ssid(buf, len)` 获取线程安全副本。
- **event_bus NAS 数据**：`event_bus_publish_nas_data()` 在 mutex 保护下拷贝到 `s_nas_data_buffer`，订阅者拿到的是只读指针。
- **触摸数据**：独立任务读取 I2C 触摸并缓存，`lvgl_touch_cb` 仅从缓存读（mutex 保护），不执行 I2C 操作。

### 配置变更反馈链路

```
UI 滑块拖动
  │
  ▼
app_cfg_set_*(value)
  ├─ 值裁剪 + g_cfg 更新
  ├─ cfg_publish(CFG_FIELD_XXX)              # 发布细粒度事件
  ├─ 衍生事件 (如 EVENT_CLOCK_LAYOUT_CHANGED)
  └─ app_cfg_save()                          # 延迟落盘 (标记脏, 1s 合并写 NVS)
  
  ▼ event_bus 队列
  
ui_event_loop 任务
  └─ UI_UPDATE(...) 刷新对应控件
```

### 背景图抓取链路

```
app_cfg_set_bg_mode(2) 或 app_cfg_set_bg_url(...)
  └─ cfg_publish + 衍生 EVENT_CLOCK_BG_CHANGED
  
ui_event_loop 收到 EVENT_CFG_CHANGED
  └─ if (field == BG_MODE || BG_URL) && bg_mode == 2:
       bg_fetcher_ensure()
         └─ xTaskCreatePinnedToCoreWithCaps(bg_fetcher_task, PSRAM 栈)
              ├─ 等 WiFi (最多 12s) + 额外 sleep 2s (避免 TLS 与 I2S DMA 争抢堆)
              ├─ bg_fetch_once(url)
              │    ├─ HTTP 流式下载到 /sdcard/clock_bg.bin.dl (4KB 缓冲)
              │    ├─ Magic 检测 (PNG/JPEG/RGB565 原始字节)
              │    ├─ 仅接受 disp_driver_get_canvas_w × disp_driver_get_canvas_h × 2 字节的 RGB565
              │    └─ rename 到 /sdcard/clock_bg.bin
              └─ event_bus_publish(EVENT_CLOCK_BG_CHANGED)
              
ui_clock 收到 EVENT_CLOCK_BG_CHANGED
  └─ 重新加载 /sdcard/clock_bg.bin 到 canvas
```

## 2.5 配置体系（单一）

详见 [模块详解 § config](03-模块详解.md#config-配置层)。要点：
- **单一配置系统** `app_cfg`（旧 `config.h/.c` 已于 v8 并入删除）
- NVS 命名空间 `"cfg"`，版本 `CFG_VERSION = 8`
- 全局实例 `g_cfg`（`app_cfg_t`），线程安全读写 `app_cfg_get_*` / `app_cfg_set_*`
- `FanConfig` 类型在 config 层 `fan_config.h`，`fan_control`（drivers）复用
- **延迟落盘（C1）**：`app_cfg_save()` 标记脏，1s esp_timer 合并写 NVS；`app_cfg_flush()` 立即落盘（关机/配网/手动保存）

## 2.6 事件总线设计

详见 [事件总线与数据流](06-事件总线与数据流.md)。核心要点：
- **同步扇出 + 异步入队**：`event_bus_publish()` 先同步调用订阅 handler，再入队；`event_bus_publish_nas_data()` 先同步调用 handler 再入队。
- **1Hz / 10Hz 心跳**：`event_bus_init()` 启动两个 esp_timer 周期发布 `EVENT_TICK_1HZ` / `EVENT_TICK_10HZ`。
- **MAX_HANDLERS_PER_EVENT = 8**：每事件最多 8 个 handler，超过静默丢弃。
- **队列长度 = 16**：硬编码，无独立任务（消费方自带任务 `event_bus_receive`）。
- **不支持 ISR 上下文**：发布函数会在定时器/任务上下文调用 `xQueueSend`。

## 2.7 网络与配网模型

### WiFi 配网 (`esp_wifi_config` 库)
- **模式**：`WIFI_PROV_ON_FAILURE`（连接失败时自动进入配网）
- **配网接口**：SoftAP（`NAS-Monitor` SSID）+ REST API（`/api/wifi/*`，Basic Auth）
- **重连策略**：`max_reconnect_attempts = 5`，耗尽后 `WIFI_ON_RECONNECT_EXHAUSTED_RESTART`
- **HTTP 模式**：`WIFI_HTTP_API_ONLY`（连接后仅保留 API，关闭配网门户）
- **多网络管理**：优先级连接，凭证存 NVS
- **禁用项**：BLE 配网（与音频栈冲突）、`WIFI_PROV_ALWAYS`（启动即配网）

### 事件桥接 (`wifi_bridge`)
| esp_bus 事件 | 项目 event_bus 事件 |
|--------------|---------------------|
| `WIFI_CFG_EVT_CONNECTED` | `EVENT_WIFI_CONNECTED` |
| `WIFI_CFG_EVT_DISCONNECTED` | `EVENT_WIFI_DISCONNECTED`（含 reason） |
| `WIFI_CFG_EVT_SCAN_DONE` | `EVENT_WIFI_SCAN_DONE` |

必须在 `wifi_cfg_init()` 之后、`ui_init()` 之前调用，确保订阅早于事件发出。

### WebUI (`webui` 组件)
- 共享 `wifi_cfg_get_httpd()` 返回的 HTTP 服务器实例，库仅注册路由不创建/销毁服务器
- 启用 Basic Auth（用户名/密码见 `user_config.h`）
- 路由：`/api/wifi-scan` (GET)、`/api/wifi-connect` (POST)、`/api/nas-settings` (GET/POST)
