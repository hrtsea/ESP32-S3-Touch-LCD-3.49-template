## 11.1 客户端族：VTable 调度与实现程度

数据层通过 `DataSource` VTable 抽象，使 `nas_event_loop` 与具体 NAS 品牌解耦（[03 §3.2](./03-模块详解.md)）。`main/CMakeLists.txt` 实际注册了 **9 个客户端源文件**：

| 源文件 | 类型 | 实现程度 |
|--------|------|----------|
| `data/client/mock_client.c` | `NAS_MOCK` | 占位（返回合成数据，用于无真机联调） |
| `data/client/api_client.c` | `NET_LINUX_HTTP` | 通用 HTTP 端点 |
| `data/client/unraid_client.c` | `NAS_UNRAID` | **真实现**（GraphQL，`unraid_client.c:17` 一次性查询 array/info/metrics/docker/vms） |
| `data/client/synology_client.c` | `NAS_SYNOLOGY` | 注册 |
| `data/client/netdata_client.c` | `NET_NETDATA` | 注册 |
| `data/client/truenas_client.c` | `NAS_TRUENAS` | 注册 |
| `data/client/qnap_client.c` | `NAS_QNAP` | 注册 |
| `data/client/serial_client.c` | `NET_LINUX_SERIAL` | 注册 |
| `data/client/snmp_client.c` | `NET_SNMP` | 注册 |

工厂入口 `data_source_create()` 据 `NasType` 选择具体 client；`data_source_poll()` 统一调用 `vtable->poll()`。

### UnraidClient 状态机要点（真实实现）

`unraid_client.c` 是已落地最完整的客户端，其关键点：

```c
// main/data/client/unraid_client.c:30
typedef struct {
    char nas_ip[40];
    uint16_t nas_port;
    char api_key[65];
    bool use_https;
    NasData data;
    uint32_t last_poll_ms;
    uint8_t consecutive_failures;   // 连续失败计数 → 用于在线/离线判定
    char* http_buf;                  // 4096 B 复用缓冲（UNRAID_HTTP_BUF_SIZE）
} UnraidClientData;
```

- **重试健壮性**：`consecutive_failures` 累计失败次数，超过阈值置 `is_online=false`，UI 自动切离线态（[10 §10.3]）。
- **温度初始值约定**：`clear_data()` 把 `temp_cpu/temp_sys` 与所有磁盘 `temp` 置 `-1`，表示"未知"，UI 据此显示 `--` 而非 0。
- **字段解析安全**：`json_get_float()` / `json_get_int()` 用 `cJSON_IsNumber` 守卫，缺失字段返回 0（不会崩溃）。
- **WiFi 闸门**：`wifi_is_connected()` 委托 `wifi_cfg_is_connected()`，与 `nas_event_loop` 的 `s_fetch_enabled` 双保险。

> 注意：经逐个核实，除 `fnos`（`mock_client_create_with_type` 占位）外，**所有品牌客户端均为真实实现**：unraid=GraphQL、synology=SID+cJSON、qnap/truenas/netdata/snmp/serial 各有完整状态机。`03-模块详解.md` 的客户端目录、工厂表、状态机表已据实更新。

## 11.2 数据模型 `NasData` 与 JSON 序列化

### 完整数据模型

`nas_data.h` 定义统一中间表示，所有客户端都填充它：

```c
// main/data/nas_data.h:110
typedef struct NasData {
    NasSystemInfo   system;                       // cpu/mem/uptime/temp/load_avg/cpu_cores[]
    NasDiskInfo     disks[MAX_DISKS];             // 每块盘温度/健康/用量/读写速率
    uint8_t         disk_count;
    uint8_t         disk_slot_count;              // 物理槽位数（UI 布局用）
    NasVolumeInfo   volumes[MAX_VOLUMES];
    uint8_t         volume_count;
    NasServiceInfo  services[MAX_SERVICES];
    uint8_t         service_count;
    NasNetworkInfo  network;                       // 单接口 rx/tx
    NasInterfaceInfo interfaces[MAX_NETWORK_INTERFACES]; // 多接口明细
    uint8_t         interface_count;
    uint8_t         active_interface_idx;
    FanStatus       fan;                           // rpm/pwm/ctrl_temp/stall_alarm
    uint32_t        last_update_ms;
    bool            is_online;
    bool            has_update;
} NasData;
```

设计要点：
- **定长数组 + count**：`disks[]`/`volumes[]`/`services[]`/`interfaces[]` 均为定长上限 + `*_count` 实际数，避免动态分配（适合 RTOS 栈/PSRAM 受限环境）。
- **`disk_slot_count` vs `disk_count`**：前者是物理槽位（决定 Overview/Storage 控件数组大小），后者是已识别盘数；UI 重建（[10 §10.5] `EVENT_DISK_CONFIG_CHANGED`）依赖 `disk_slot_count`。
- **健康状态枚举** `HealthStatus{OK,WARNING,CRITICAL,UNKNOWN}`：UI 据此着色。
- **`temp_cpu == -1` 约定**：缺测温度，UI 显示 `--`。

### 双向 JSON 序列化（配网调试用途）

`nas_data_json.c` 提供 `nas_data_to_json()` / `nas_json_to_data()`，是 **BLE 配网 CLI 调试**的桥梁——`cli.c` 通过 BLE/串口把 `NasData` 序列化为 JSON 供手机端预览，反向把手机下发 JSON 回灌到 `NasData`。

```c
// main/data/nas_data_json.c:5
cJSON *nas_data_to_json(const NasData *data) {
    cJSON *root = cJSON_CreateObject();
    /* system / disks[循环] / volumes / services / network / is_online ... */
}
```

- 序列化对所有数组用 `for (i < *_count && i < MAX_*)` 双上限保护，防越界。
- 反序列化 `nas_json_to_data()` 用 `strncpy(..., sizeof(dst)-1)` 防字符串溢出（`nas_data_json.c:85`）。
- JSON 仅含可序列化字段，**不含** `http_buf`、`consecutive_failures` 等运行时内部状态。

## 11.3 风扇温控算法（`fan_control.c`）

风扇子系统是本项目少有的**带控制环**的硬件模块，独立于数据/UI 事件流，自起任务 `fan_control_task`。

### 控制环（每 `FAN_CONTROL_PERIOD_MS` 一次）

```c
// main/data/fan_control.c:156
static void fan_control_task(void *arg) {
    while (1) {
        s_current_rpm = fan_pcnt_read_rpm();                 // PCNT 测速
        memcpy(&cfg_snapshot, &g_config.fan, sizeof(FanConfig)); // 读配置副本(线程安全)
        if (!cfg_snapshot.enabled)            target = 0;     // 关闭
        else if (MANUAL)                      target = manual_pwm_pct;
        else { /* AUTO */
            temp = select_ctrl_temp(temp_source);             // CPU/SYS/AVG/MAX 选源
            if (emergency_temp>0 && temp>=emergency_temp) target = 100;  // 紧急全速
            else target = eval_curve(temp, curve);            // 曲线插值
            if (target < min_pwm_pct) target = min_pwm_pct;   // 最低占空比
            if (abs(diff) < hysteresis ...)  target = s_current_pwm;  // 滞回防抖
            if (abs(diff) < min_change_pct)  target = s_current_pwm;  // 最小变化阈值
        }
        fan_ledc_set_duty_pct(target);
        /* 停转检测：pwm>min 且 rpm==0 持续 stall_detect_sec → stall_alarm */
    }
}
```

### 关键算法

1. **曲线线性插值**（`eval_curve`，`fan_control.c:50`）：在 `FAN_CURVE_POINTS` 个点构成的折线中按温度线性插值 PWM，边界钳位置曲线端点；结果限幅 [0,100]。
2. **温度源选择**（`select_ctrl_temp`，`fan_control.c:33`）：`TEMP_CPU_ONLY / SYS_ONLY / AVG_CPU_SYS / MAX_CPU_SYS` 四选一。
3. **双级防抖**：`hysteresis`（滞回，避免临界温度频繁抖动）+ `min_change_pct`（最小变化阈值，减少 PWM 跳变）。
4. **停转检测**：`pwm>min_pwm` 但 `rpm==0` 持续 `stall_detect_sec` 秒置 `stall_alarm`，经 `EVENT_FAN_STATUS_UPDATE`（每 `FAN_STATUS_PUBLISH_MS`，`fan_control.c:235`）对外发布。
5. **紧急温度保护**：`temp>=emergency_temp` 直接强制 100% 全速。

### 硬件接口

- **PWM 输出**：`LEDC`（APB 时钟，频率/分辨率由 `FAN_PWM_*` 宏定义），`fan_ledc_set_duty_pct()` 把百分比映射到 `duty = max_duty * pct / 100`（`fan_control.c:99`）。
- **转速反馈**：`PCNT`（脉冲计数 + 滤波），`RPM = count*60 / FAN_PULSES_PER_REV`（`fan_control.c:147`），采样窗口 `FAN_RPM_SAMPLE_MS`。
- **温度注入**：`fan_control_on_nas_data()` 由 UI 事件循环在收到 `EVENT_NAS_DATA_UPDATE` 时调用，把 `temp_cpu/temp_sys` 写入受 `s_state_mux` 保护的内部态（`fan_control.c:317`）。
- **配置热更新**：`fan_control_apply_config()` 仅打日志——下一轮循环自动读 `g_config.fan`（`fan_control.c:298`），无需显式同步。

## 11.4 组件层接口边界

`main` 通过 `main/CMakeLists.txt` 的 `REQUIRES` 引入 24 个组件（含自定义 BSP + 第三方库）。其中与本板硬件强相关的两个自研组件对外接口如下。

### `lcd_bl_pwm_bsp`（背光 PWM）

```c
// components/lcd_bl_pwm_bsp/lcd_bl_pwm_bsp.h:23
void lcd_bl_pwm_bsp_init(uint16_t duty);
void setUpduty(uint16_t duty);
```

- 亮度用 **反向** 占空比宏：`LCD_PWM_MODE_0 = 0xff-0`（全亮）…`LCD_PWM_MODE_255 = 0xff-255`（全暗）（`lcd_bl_pwm_bsp.h:6`）。注意：值越大越暗，调用方需按此约定传参。
- 由 `hw_init.c` / `disp_driver.c` 在显示初始化阶段调用。

### `i2c_bsp`（I²C 外设总线）

```c
// components/i2c_bsp/i2c_bsp.h:14
void i2c_master_Init(void);
uint8_t i2c_writr_buff(i2c_master_dev_handle_t dev, int reg, uint8_t *buf, uint8_t len);
uint8_t i2c_read_buff (i2c_master_dev_handle_t dev, int reg, uint8_t *buf, uint8_t len);
uint8_t i2c_master_write_read_dev(dev, wbuf, wlen, rbuf, rlen);
uint8_t i2c_master_touch_write_read(dev, wbuf, wlen, rbuf, rlen);

extern i2c_master_dev_handle_t disp_touch_dev_handle;  // 触摸
extern i2c_master_dev_handle_t rtc_dev_handle;         // 实时时钟
extern i2c_master_dev_handle_t imu_dev_handle;         // 惯性传感器
extern i2c_master_bus_handle_t esp_i2c_bus_handle;
```

- 总线单例 `esp_i2c_bus_handle` + 三个已注册设备句柄（触摸/RTC/IMU）以 `extern` 暴露，避免重复初始化。
- `i2c_master_touch_write_read` 是触摸面板专用读序列（与通用 `i2c_master_write_read_dev` 分离）。

> 其余 REQUIRES 组件（audio 相关 `esp_audio_simple_player`/`recorder`/`radio`、SD 卡 `sdcard_bsp`、`button_bsp`、`usb_hid_bsp`、`rgb_led`、`webui` 等）为模板板载能力，本项目仅 `disp_driver`/`i2c_bsp`/`lcd_bl_pwm_bsp`/`rgb_nas_monitor` 被实际驱动代码调用，其余多为板级预留。

## 11.5 构建系统与内存调优（工程决策）

### 顶层构建（`CMakeLists.txt`）

```cmake
# CMakeLists.txt:10
set(EXCLUDE_COMPONENTS audio_bsp codec_board espressif__esp_codec_dev)
```

- **排除 audio 组件**：注释说明 IDF 5.2.x 下 `esp_codec_dev` 引入 legacy `driver/i2c.c`，与 new `i2c_master` 驱动冲突导致构造函数 abort，`app_main` 无法运行。这是**已知坑**，升级 IDF 时需重估。
- 根 `project(12_HelloWorld_Skeleton)` 名称沿用模板，与实际产品名不符（建议改名但非必须）。

### main 组件注册（`main/CMakeLists.txt`）

- 显式列出 **59 个源文件**（UI 屏 + 字体 + 驱动 + 数据 + 工具），无通配——新增 `.c` 必须手动加入否则不被编译（常见踩坑点）。
- `REQUIRES` 引入 24 个组件；`--whole-archive` 强制链接 `radio`/`recorder` 静态库（因 webui 反向引用而链接顺序无法自动解析，`main/CMakeLists.txt:108`）。

### `sdkconfig.defaults` 关键内存决策

这是本项目**最易翻车的配置区**，注释已记录工程教训：

| 配置 | 值 | 决策原因 |
|------|-----|----------|
| `CONFIG_SPIRAM=y` + `MODE_OCT` + `SPEED_80M` | — | Octal PSRAM，240 MHz 主频 |
| `CONFIG_LV_COLOR_16_SWAP=y` | — | 屏 RGB565 字节序交换 |
| `CONFIG_LV_MEM_CUSTOM=y` + `LV_MEMCPY_MEMSET_STD` | — | LVGL 用标准 malloc，便于接入 PSRAM |
| `CONFIG_LV_IMG_CACHE_DEF_SIZE=2` | — | 仅缓存 2 张图，省 DRAM |
| **禁用** `CONFIG_LV_USE_PNG`/`SJPG` | — | lodepng/tjpgd 静态表占 DRAM ~50KB，导致 radio_init 的 I2S DMA 分配失败（背景图回退 raw RGB565） |
| `CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=512` | 512 | 小分配留 DRAM（热路径），大分配走 PSRAM，防 radio_init `ESP_ERR_NO_MEM` |
| `CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC=y` | — | mbedTLS ~30KB ctx 从 PSRAM 分配，避免 HTTPS 握手 `ESP_ERR_MBEDTLS_SSL_SETUP_FAILED` |
| `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y` | — | 控制台走 USB-Serial-JTAG，日志与 shell 同口 |
| `CONFIG_TINYUSB_HID_ENABLED=y` | — | USB HID 按钮事件 |

> 核心矛盾：**internal DRAM 极度紧张**（LVGL widget 树 + I2S DMA + mbedTLS ctx 争抢）。所有调优都围绕"把大块/冷分配推到 PSRAM，把小块/热分配留 DRAM"。改 DRAM 相关 LVGL/音频选项前务必回看这些注释。
