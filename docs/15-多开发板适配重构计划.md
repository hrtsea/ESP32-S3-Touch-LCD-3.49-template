# 15. 多开发板适配重构计划

> 目标：将当前仅支持 **ESP32-S3-Touch-LCD-3.49"**（AXS15231B / QSPI / 172×640 面板 / CST 触摸）的工程，重构为**可扩展的多开发板框架**，支持不同屏幕控制器、接口类型与分辨率。
>
> 版本：v0.1（规划稿）
> 状态：已确认方案 —— 首批**只做框架 + 当前板回归**；UI 适配采用**按分辨率档位走不同布局**。

## 1. 背景与目标

### 1.1 现状问题

当前工程把"硬件板级参数"与"应用逻辑"深度耦合，具体表现为：

1. **板级参数集中但单一**：[user_config.h](../main/user_config.h) 中所有 GPIO、分辨率、接口参数均为 3.49" 板写死，无法切换。
2. **显示驱动与面板强绑定**：[disp_driver.c](../main/drivers/disp_driver.c) 直接调用 `esp_lcd_new_panel_axs15231b`（QSPI 专有）、写死 `s_lcd_init_cmds`、旋转逻辑 `flush_rot0/90/180/270`、CST 触摸协议（0xb5 0xab 0xa5 0x5a 命令流）。
3. **触摸读取内嵌在显示驱动中**：`touch_read_task` 直接操作 I2C 设备句柄与触摸 IC 协议，与面板驱动耦合。
4. **UI 大量硬编码分辨率**：`ui/screens/` 下 66 处 `640` / `172` 写死（如 [ui_Screen_Overview.c](../main/ui/screens/ui_Screen_Overview.c#L149) 的 `lv_obj_set_size(status_bar, 640, 35)`），换分辨率即失效。
5. **外设初始化串行写死**：[hw_init.c](../main/utils/hw_init.c) 无条件初始化 TCA9554 / 背光 / RTC / IMU / ADC / 音频 / 风扇 / SD / 按键，不区分板型能力。

### 1.2 重构目标

- 建立 **board 抽象层**：每块开发板一个配置实现，编译期选择。
- **面板驱动接口化**：解耦 disp_driver 与具体屏幕控制器（QSPI / SPI / RGB）。
- **触摸驱动接口化**：解耦 CST / GT911 / FT6X36 等触摸 IC。
- **分辨率抽象**：逻辑画布尺寸运行时获取，UI 按分辨率档位选择布局。
- **外设按板能力可选**：TCA9554、背光、音频等按 board 配置决定是否初始化。
- **当前 3.49" 板功能回归不变**（框架改造不改变现有行为）。

## 3. 目标架构

### 3.1 分层视图

```
┌─────────────────────────────────────────────────────────┐
│  app 层  main/ (main.cpp, ui/, data/, config/, utils/)  │
│         —— 与硬件解耦，只依赖 board API 与 disp API      │
├─────────────────────────────────────────────────────────┤

│   ├─ panel_driver.h     面板驱动接口（薄层定义）        │
│   ├─ touch_driver.h     触摸驱动接口（薄层定义）        │
│   ├─ storage_driver.h   存储驱动接口（薄层定义）        │
│   ├─ res_class.h        分辨率档位                      │
│   └─ esp32s3_touch_lcd_3_49/  当前板实现（显示/触摸     │
│        驱动随 board 内聚，同目录维护）                  │

├─────────────────────────────────────────────────────────┤
│  components/  BSP 组件（i2c_bsp / lcd_bl_pwm_bsp / …）   │
│  含芯片寄存器级驱动（esp_lcd_axs15231b 等 espressif     │
│  managed components，由 board 驱动调用，不重复实现）     │
└─────────────────────────────────────────────────────────┘
```

### 3.2 关键设计决策

1. **board 层位置**：放在 `main/boards/`（不修改 `components/`，遵循项目约束）。通过 `main/CMakeLists.txt` 的 `INCLUDE_DIRS` 接入。
2. **选择机制**：编译期宏 `CONFIG_BOARD_NAME`（Kconfig 提供选项），CMake 依据宏只编译对应 `boards/<name>/` 下的源文件。
3. **板描述结构体**：一个 `const board_desc_t`，集中描述屏幕接口、分辨率、GPIO、触摸、外设能力。
4. **disp_driver 保留对外 API**：`lvgl_lock/unlock`、`disp_driver_init/update_resolution`、FPS 统计等签名不变，内部改为调用 board 接口，UI 层无感。
5. **分辨率运行时化**：`UI_CANVAS_W/H` 从 `#define` 改为由 `disp_driver_get_canvas_w/h()` 运行时获取；物理分辨率由 `board_desc_t` 提供。
6. **UI 布局按分辨率档位分支**：定义 `res_class_t` 枚举，屏幕初始化时按档位选择布局参数。
7. **显示/触摸驱动随 board 内聚**：接口（`panel_driver_t` / `touch_driver_t`）只在 `boards/` 根定义薄层，实现（`panel_axs15231b_qspi.c` / `touch_cst.c` 等）放在各自 `boards/<name>/` 目录下与 `board.c` 同目录维护。理由：面板/触摸的引脚、初始化序列、分辨率、旋转、触摸接线全部是**板级资源**，不同板即使同一显示芯片也可能引脚与分辨率不同，驱动与 board 同目录最内聚；`disp_driver.c` 仅依赖接口，保持通用。
8. **芯片寄存器级驱动不重复造轮子，来源双渠道**：QSPI/SPI/RGB 面板的寄存器操作优先由 espressif 组件提供（如现有 `esp_lcd_axs15231b`，后续 ST7789/GC9A01/ST7262 同理通过 `idf_component.yml` 引入）；**若 espressif 无对应芯片支持，则把 vendor 驱动拷贝进 `boards/<name>/vendor/`（决策 12）**。`boards/<name>/` 下的板级驱动只负责接线、初始化序列编排与调用它们。这样新增显示芯片 = 新增一个板级 panel 实现 + 声明组件依赖或 vendor 拷贝，不修改公共层。
9. **LVGL flush / DMA 机制整体下沉到面板驱动**：旋转策略、分条方式、DMA/buffer 分配都是**接口类型相关**的（详见 4.2 差异表），不是通用逻辑：
   - RGB 接口：整帧 PSRAM 帧缓冲 + LCD_CAM DMA，无 CPU 旋转、无分条；
   - SPI 接口：面板 MADCTL 寄存器旋转，flush 直通，DMA 缓冲在 internal RAM；
   - QSPI 接口（当前 3.49"）：CPU 侧 90° 像素变换 + 分条 + SPI DMA。
   `panel_driver_t` 因此提供 `create_buffers()`（分配 draw_buf，buffer 大小/位置因接口而异）、`flush_cb`（LVGL flush 回调，旋转/分条/DMA/完成通知由实现内部完成）与 `setup_disp_drv()`（填充 `lv_disp_drv_t` 中板相关字段）。`disp_driver.c` 只保留与面板无关的 LVGL 集成：`lv_init`、disp/indev 注册、tick 定时器、mutex、LVGL 任务、FPS 统计、分辨率动态更新。
10. **disp_driver 不下放，但注册参数来自面板驱动**：`disp_driver` 是 LVGL 运行时集成层（任务调度 / tick / mutex / FPS / webui 帧缓冲对接），对任何板都相同；UI 层、webui、CLI、模拟器 override 都依赖其稳定 API，整体下放到 board 会把依赖打散、改动面大且无收益。所有板差异（画布分辨率、draw_buf、flush_cb、`full_refresh`/`direct_mode`、`user_data`）通过 `panel_driver->setup_disp_drv()` 收敛，disp_driver 不硬编码任何注册值。
11. **存储/SD 驱动随 board 自包含**（对齐 HomeTiles）：SD 的挂载逻辑、引脚、格式化随 board 内聚为 `storage_driver_t`，不依赖 `components/sdcard_bsp`。引脚写入 `board_desc_t.sd`（见 4.1），挂载逻辑迁移到 `boards/<name>/storage_sdmmc.c`（逻辑同 [sdcard_bsp.c](../components/sdcard_bsp/sdcard_bsp.c)，引脚参数化）。**兼容策略**：webui / recorder 等不可改组件链接的是 `sdcard_bsp` 的符号（`sdcard_is_mounted` / `sdcard_format` / `sdcard_busy` 等），因此板级实现**导出同名符号**作为适配层转发到 storage 驱动，同时把 `sdcard_bsp` 从 `EXCLUDE_COMPONENTS` 排除（与 audio_bsp / codec_board 同先例，见 4.6）。`components/` 内文件本身零改动。
12. **board 层可直接拷贝 vendor 驱动**（`boards/<name>/vendor/` 收容区）：新增板时，若 espressif 组件无对应芯片支持，可把厂商提供的驱动放入 board 的 `vendor/` 子目录，由 `panel_driver_t` / `touch_driver_t` 薄壳调用，**不要求重写芯片驱动**。按 vendor 驱动形态分三级：
    - **A. 原样拷贝**：vendor 提供 ESP-IDF / `esp_lcd` 风格驱动（无 Arduino 依赖、无 IDF 版本冲突）→ 原样进 `vendor/`，薄壳只需接线与初始化序列；
    - **B. 移植后使用**：vendor 提供 Arduino 库（TFT_eSPI / LovyanGFX 等，依赖 Arduino core 的 Wire/SPI 包装）→ 需移植到 IDF 原生 API 后进 `vendor/`；若整板生态强依赖某全能库，可另议"以库为抽象层"路线（默认不采用）；
    - **C. 参考重写**：vendor demo 混乱 / 硬编码 / 版本过旧 → 只参考其寄存器初始化序列，自写简洁实现（当前 3.49" 板即此路线，寄存器级走 esp_lcd 组件）。
    注意事项：vendor 文件须有许可证可商用；接入 `boards/<name>/` 的 CMake 构建；警惕 vendor 驱动使用旧 IDF API（如 `i2c_driver` vs `i2c_master`，本项目已有 audio_bsp / codec_board 因 I2C API 冲突被排除的先例）；`components/` 内已有文件仍不可修改，vendor 新文件放 `boards/<name>/vendor/` 不受此限。

## 4. 技术设计

### 4.1 板描述结构体（board_desc_t）

```c
/* boards/board.h */
typedef struct {
    const char *name;          /* "esp32s3_touch_lcd_3_49" */

    /* 屏幕接口类型 */
    enum { LCD_IF_QSPI, LCD_IF_SPI, LCD_IF_RGB } lcd_if;

    /* 物理面板分辨率（写入面板驱动） */
    int panel_h_res, panel_v_res;
    /* 逻辑 LVGL 画布分辨率（横屏语义） */
    int canvas_w, canvas_h;
    /* 默认旋转：0/90/180/270 */
    int default_rotation;

    /* 旋转模式：四档 90° 旋转，还是仅 180° 翻转
       （竖屏 QSPI 面板 CPU 旋转换算 → QUARTER；横屏 RGB/带 MADCTL 面板 → FLIP） */
    enum { ROT_STEP_QUARTER, ROT_STEP_FLIP } rotation_step_mode;

    /* 分条 flush 行数（替代 LVGL_FLUSH_STRIP_ROWS，面板驱动分配 buffer 时使用） */
    uint8_t display_flush_bands;

    /* 分辨率档位：决定 UI 走哪张布局参数表（见 4.4） */
    res_class_t res_class;

    /* 背光 */
    struct {
        int gpio, pwm_channel, max_brightness;
        uint8_t min_input;     /* 最小可见输入值（>= 此值映射为 1% 亮度） */
    } backlight;

    /* 面板 GPIO */
    struct {
        int cs, pclk, data0, data1, data2, data3, rst;
        int dc;                /* SPI 接口使用，QSPI 为 -1 */
    } panel_pins;

    /* 触摸 */
    struct {
        int i2c_port;          /* 复用 i2c_bsp 总线 */
        uint8_t addr;
        int rst_gpio, int_gpio;
        int h_res, v_res;      /* 物理触摸坐标上限 */
    } touch;

    /* LVGL 任务时序（不同 SoC 负载差异可调） */
    struct {
        int tick_period_ms;      /* 原 EXAMPLE_LVGL_TICK_PERIOD_MS */
        int task_max_delay_ms;   /* 原 EXAMPLE_LVGL_TASK_MAX_DELAY_MS */
        int task_min_delay_ms;   /* 原 EXAMPLE_LVGL_TASK_MIN_DELAY_MS */
    } lvgl_timing;

    /* SD 存储（storage 驱动使用，替代 sdcard_bsp 硬编码引脚；
       是否启用由 periph.sd 位图决定） */
    struct {
        bool   sdmmc;            /* true=SDMMC 主机，false=SDSPI */
        int    clk, cmd, d0;     /* SDMMC 引脚（3.49": 41/39/40） */
        int    width;            /* 数据线宽 1/4 */
        uint32_t max_freq_khz;   /* 原 SDMMC_FREQ_DEFAULT */
        int    mount_max_files;  /* 原 max_files=5 */
        bool   internal_pullup;  /* 原 SDMMC_SLOT_FLAG_INTERNAL_PULLUP */
        bool   auto_format;      /* format_if_mount_failed（现为 false） */
    } sd;

    /* 外设能力位图 */
    struct {
        bool tca9554;          /* IO 扩展器电源控制 */
        bool rtc, imu, adc, audio, fan, sd, button, rgb;
    } periph;
} board_desc_t;

const board_desc_t *board_get(void);
```

### 4.2 面板驱动接口（panel_driver.h）

接口只在 `boards/` 根定义，实现随各板目录内聚。flush 回调和 buffer 分配都下沉到面板驱动：

```c
/* boards/panel_driver.h —— 薄层接口 */
typedef struct {
    const char *name;
    int         if_type;   /* LCD_IF_QSPI / LCD_IF_SPI / LCD_IF_RGB */

    /* 面板硬件初始化（总线 / panel io / 寄存器序列） */
    esp_err_t (*init)(void);

    /* 分配 LVGL draw_buf：buffer 大小/位置因接口而异
       （QSPI/SPI → internal DMA RAM 分条；RGB → PSRAM 整帧） */
    esp_err_t (*create_buffers)(lv_disp_draw_buf_t *draw_buf);

    /* 填充 lv_disp_drv_t 中与面板相关的字段：
       hor_res / ver_res（画布）、flush_cb、draw_buf、
       full_refresh / direct_mode、user_data —— 板差异全部收敛于此，
       disp_driver 不硬编码任何注册值 */
    void (*setup_disp_drv)(lv_disp_drv_t *drv);

    /* 面板级旋转（支持 MADCTL 的面板走寄存器；不支持的在 flush 内做 CPU 变换） */
    esp_err_t (*set_rotation)(int rot);
} panel_driver_t;

const panel_driver_t *panel_driver_get(void);
```

**disp_driver 不下放**：它是 LVGL 运行时集成层，对任何板相同，且 UI/webui/CLI/模拟器 override 都依赖其 API。板差异仅通过上述回调进入 disp_driver：

```c
/* disp_driver.c —— LVGL 集成（通用），无任何板级常量 */
const panel_driver_t *pd = panel_driver_get();
pd->init();
pd->create_buffers(&s_disp_buf);          /* draw_buf 由面板驱动分配 */
lv_disp_drv_init(&disp_drv);
pd->setup_disp_drv(&disp_drv);            /* 注册参数全部来自面板驱动 */
lv_disp_drv_register(&disp_drv);
```

**flush 机制差异对照（驱动实现内部各写各的）：**

| 环节 | QSPI（当前 3.49"） | SPI（ST7789/GC9A01 等） | RGB（ST7262 等） |
|------|------|------|------|
| 旋转 | CPU 侧 90° 像素变换（迁移 [flush_rot90 等](../main/drivers/disp_driver.c#L101)） | MADCTL 寄存器旋转，flush 直通 | 扫描方向寄存器配置 |
| 分条 | 128 行 × 面板宽分条（[LVGL_FLUSH_STRIP_ROWS](../main/user_config.h#L32)） | 按 DMA buffer 分条 | 整帧，无分条 |
| DMA | SPI DMA + internal RAM（[MALLOC_CAP_DMA](../main/drivers/disp_driver.c#L416)） | SPI DMA + internal RAM | LCD_CAM DMA + PSRAM 帧缓冲 |
| 完成通知 | on_color_trans_done ISR → semaphore | 同左 | VSYNC/HSYNC 回调 |

```c
/* boards/esp32s3_touch_lcd_3_49/panel_axs15231b_qspi.c —— 板级实现 */
static esp_err_t panel_init(void);    /* QSPI 总线 + esp_lcd_axs15231b 组件 + 板级引脚/时序 */
static esp_err_t create_buffers(lv_disp_draw_buf_t *db);  /* 2 块 DMA 条缓冲 + 画布 fb */
static void flush_cb(lv_disp_drv_t *drv, const lv_area_t *a, lv_color_t *cm);
    /* CPU 旋转 + 分条 + semaphore 同步 */
static void setup_disp_drv(lv_disp_drv_t *drv);
    /* hor_res/ver_res = canvas；flush_cb = flush_cb；direct_mode=1；user_data=panel */
const panel_driver_t panel_driver = { "axs15231b_qspi", LCD_IF_QSPI,
                                      panel_init, create_buffers,
                                      setup_disp_drv, set_rotation };
```

- 寄存器级操作复用 espressif 组件（`esp_lcd_axs15231b`、后续 `esp_lcd_gc9a01` / `esp_lcd_st7789` 等）。
- 新显示芯片/新接口 = 新建一个 `boards/<name>/panel_xxx.c` 实现 + `idf_component.yml` 声明组件，公共层零改动。
- 初始实现 `panel_axs15231b_qspi`：迁移现有 [lcd_init](../main/drivers/disp_driver.c#L344) + [lvgl_flush_cb](../main/drivers/disp_driver.c#L173) + [lvgl_init 中 buffer 分配](../main/drivers/disp_driver.c#L416) 的逻辑。

```c
/* 状态栏：多屏共享的构建函数，从参数表取锚点 */

    lv_obj_align(s_screen.label_down,  LV_ALIGN_LEFT_MID, L->status_x_down, 0);

    lv_obj_align(s_screen.icon_wifi,   LV_ALIGN_LEFT_MID, L->status_x_wifi, 0);
    lv_obj_align(s_screen.icon_bt,     LV_ALIGN_RIGHT_MID, L->status_bt_ofs_x, 0);
    /* divider: 宽=画布宽，高=L->status_divider_h */
}

/* 总览内容区 */
static void ui_overview_area_create(lv_obj_t *parent) {
    const layout_profile_t *L = layout_get();
    lv_obj_t *cpu = lv_obj_create(parent);            /* 240×100 @ (0,37) */
    lv_obj_set_size(cpu, L->cpu_w, L->cpu_h);
    lv_obj_align(cpu, LV_ALIGN_TOP_LEFT, 0, L->content_y);

```

**覆盖规则**：`layout_get()` 返回当前 `res_class` 的静态表；若某块板在同一档位内有微调（如同一档不同画布宽），可在 `board.c` 中提供该板专属表覆盖档位默认表（`board_desc_t.layout` 指针优先）。

**可选的进阶（状态栏彻底字段化）**：状态栏字段在详情页与总览页锚点略异（如 Detail 多"返回"按钮、time 从 110 移到 160）。若后续档位增多，可将状态栏改为"字段数组"（`{kind, x}[]`）驱动，首批用固定坐标字段即可。

## 6. 风险与约束

| 风险/约束 | 应对 |
|----------|------|
| UI 去硬编码改动面大，易引入视觉回归 | 每屏独立改造 + 模拟器截图对比（`sim/test_screenshots/`） |
| `user_config.h` 被大量文件引用，直接改宏定义风险高 | 阶段 1 采用"board 提供同义宏"最小侵入迁移，后续再收敛 |
| 旋转/分条/DMA 与接口类型强相关 | flush 回调与 buffer 分配整体下沉到面板驱动，disp_driver 仅做 LVGL 集成 |
| `components/` 不可修改（项目约束） | board 层全部放在 `main/boards/`，BSP 组件接口保持不变 |
| `-Wno-error=stringop-truncation` 等编译选项需保留 | 根 CMakeLists 构建选项不动 |
| 模拟器与真实硬件的屏驱动差异 | 模拟器继续使用 `sim_overrides/disp_driver.c`，不参与 board 面板驱动编译 |

## 7. 里程碑

| 里程碑 | 内容 | 出口标准 |
|--------|------|---------|
| M1 | 阶段 0 + 1 完成 | board 框架落地，3.49" 板回归通过 |
| M2 | 阶段 2 完成 | 显示/触摸驱动与板级面板解耦 |
| M3 | 阶段 3 完成 | UI 分辨率档位化，无裸魔数 |
| M4 | 阶段 4 + 5 完成 | 外设可裁剪，新板适配流程文档就绪 |

## 附录 A：参考项目 HomeTiles 分析

> 来源：https://github.com/GalusPeres/HomeTiles （ESP32 智能家居瓦片面板，Arduino 框架），2026-08 克隆调研。用于校验本计划的分层设计并提取可借鉴点。

### A.1 它的多硬件兼容机制

**① 编译期设备选择 + 家族宏**（`src/devices/device_select.h`）
- `DEVICE_XXX` 宏唯一选定目标设备（Arduino IDE 手动改注释，CI 用 `HOMETILES_CI_TARGET` 编译 flag）；互斥检查（选多于一个直接 `#error`）。
- 自动推导**家族宏**：`DEVICE_WAVESHARE_TOUCH_LCD_X`（7/8/10.1" 同基板共享电源/I2C/SD/网络接线）、`DEVICE_GUITION_JC8012P4A1_FAMILY`、`DEVICE_ESP32_S3_RGB_480`、`DEVICE_LAYOUT_1024X600`（布局复用）等，供公共代码条件编译。

**② 命名空间别名静态分发**（`active_device.h` → `device.h` → `device.cpp`）
- `namespace DeviceImpl = DeviceWaveshareTouchLCD7;` 编译期绑定到唯一设备。
- `Device::init()` / `Device::displayPushPixels()` / `Device::getTouch()` 等一律转发到 `DeviceImpl::xxx()`，**零虚函数开销**。
- 每个设备必须实现一整套同名接口：init/update、显示（PushPixels/DMA/全帧预览/填屏/旋转）、触摸、背光、休眠/唤醒/功耗、SD/存储/迁移、重启前处理。

**③ Profile 元数据（constexpr，数据驱动 UI 几何）**（`device_types.h` + 各设备 `profile.h`）
```cpp
inline constexpr Device::Profile kProfile{
    "waveshare_touch_lcd_7", "Waveshare Touch LCD 7",
    1280, 720,      // 逻辑分辨率（横屏）
    7, 4, 16, 4,    // grid_cols/rows/gap/pad
    168, 166,       // grid_cell_w/h
    4, 121,         // display_flush_bands / backlight_input_min
    RotationStepMode::FlipOnly, 0, 2,   // 旋转模式/默认/翻转
    Capabilities{...},                 // has_battery/imu/auto_rotation/usb_net/native_eth
    kHardwareIoProfile,                // 引脚能力表
};
```
- UI 直接读 `Device::kScreenWidth` / `kGridCols` 等**编译期常量**，布局几何完全数据驱动，无逐屏分支。
- `RotationStepMode` 区分「可 90° 四档旋转」与「仅 180° 翻转」——正是竖屏 QSPI 面板与横屏 RGB 面板的差异。

**④ 设备实现完全自包含**（`device_waveshare_touch_lcd_7.cpp` 等，`#if defined(DEVICE_XXX)` 包裹）
- 面板初始化各写各的：DSI-MIPI（ILI9881C/JD9365）、RGB、SPI；旋转用 PPA 硬件 SRM 加速 + CPU 变换兜底；帧缓冲策略各异（DPI framebuffer 直写 / DMA 条缓冲）。
- 触摸、背光、SD、存储、功耗全部随设备，互不共享硬编码。

**⑤ 发布/CI**：每设备独立 build target、OTA 固件 key、CI 构建矩阵、Web 管理端设备名；未在真机验证前标为 experimental。

### A.2 与当前计划的对照

| HomeTiles | 本计划 | 结论 |
|-----------|--------|------|
| `DEVICE_XXX` + 家族宏 | `CONFIG_BOARD_NAME`（Kconfig/CMake） | 机制一致；可借鉴**家族宏**（见启示 1） |
| namespace `DeviceImpl` 静态分发 | `panel_driver_t` / `touch_driver_t` 函数指针 | C 项目函数指针为标准做法，等价 |
| Profile constexpr（含 grid 几何） | `board_desc_t` + `res_class_t` 档位 | 可借鉴：**布局几何数据化**（见启示 2） |
| `Capabilities` 位图 | `periph.*` 位图 | 一致 |
| 设备实现自包含（含 SD/存储/功耗） | 存储随 board 内聚（`storage_driver_t`），其余 BSP 不动 | **已采纳**（决策 11）：SD 挂载/引脚/格式化迁移到 `boards/<name>/`，经同名符号适配层兼容不可改组件（见 4.6） |
| 布局复用宏 `DEVICE_LAYOUT_*` | `res_class_t` 运行时档位 | 机制等价，宏 vs 运行时 |

### A.3 对重构计划的启示（2、3 已采纳，1 待确认）

1. **引入"板家族"概念**：HomeTiles 同基板多面板用家族宏共享公共代码（如 Waveshare X 系列）。本计划 `boards/` 可预留 `board_family.h` 家族推断，避免将来同基板不同屏时复制整块板代码。
2. **布局几何数据化进 Profile**：**已采纳** —— `res_class` 档位 + `layout_profile_t` 静态参数表（见 4.4），UI 读 `layout_get()` 而非写分支；`rotation_step_mode`、`display_flush_bands`、`backlight.min_input` 已纳入 `board_desc_t`（见 4.1）。
3. **Profile 关键字段可复制**：`rotation_step_mode`（四档旋转 vs 仅翻转）、`display_flush_bands`（分条行数）、`backlight_input_min`（背光线性段）正好对应本项目的面板差异点，建议直接纳入 `board_desc_t` —— **已采纳**，字段见 4.1。

（备注：HomeTiles 为 Arduino/C++ 项目，本计划为 ESP-IDF/C 项目，机制仅作架构参考，不复用代码。）
